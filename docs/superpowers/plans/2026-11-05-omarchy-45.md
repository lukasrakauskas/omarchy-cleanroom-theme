# Cleanroom Omarchy 4.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Cleanroom's generated Neovim theme resemble GitHub Light, then check terminal applications.

**Architecture:** Keep Omarchy 4.5's data-only theme pipeline and generated Aether integration. Tune palette assignments for Neovim, preserve blue accent and yellow selections, and retain app-specific data themes where semantic remapping would hurt readability.

**Tech Stack:** TOML, Python unittest, Omarchy 4.5 Bash template generator, headless Neovim and installed Aether v3.

**Spec:** `docs/superpowers/specs/2026-11-05-omarchy-45-design.md`

## Global Constraints
- Preserve the existing set of GitHub Light colors, white canvas, blue desktop accent (`#005cc5`), and yellow Visual selection (`#fed442`).
- Exact equivalence with the GitHub plugin is not required.
- Never edit `/usr/share/omarchy`.
- No local Neovim configuration or executable theme hooks are needed.
- Do not reset unrelated user configuration or commit changes without a request.

## Review Focus
- Git-installed themes discard Lua and terminal configurations: tests must model that staging boundary.
- Templates must resolve fully without new plugin downloads or changes to the real HOME during testing.
- ANSI aliases must not contradict semantic assignments; any retained aliases must stay synchronized.
- Yellow Visual selection must remain readable with black text; search is a documented separate behavior.
- Generated app themes must keep blue primary accents and valid JSON/TOML, despite syntax-driven palette assignments.
